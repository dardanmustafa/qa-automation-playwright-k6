# BUG-012 · QuickPizza: no compression and no caching headers, even on static files

| Field | Value |
|---|---|
| Severity | Minor (performance) |
| Priority | Low |
| Area | QuickPizza › web server configuration |
| Environment | <https://quickpizza.grafana.com> |
| Reproducible | Always |
| Found by | HTTP/S response analysis during the load test ([`docs/load-test/response-analysis.txt`](../docs/load-test/response-analysis.txt)) |

## Summary

1. **No compression.** Answers are never compressed, although every request says `Accept-Encoding: gzip, br`.
2. **No caching headers.** Static files whose names contain a content hash (they can never change) are sent without any caching information: no `Cache-Control`, `ETag` or `Last-Modified`.
3. **Unneeded cookie.** A load-balancer cookie (`AWSALB`) is set on every answer, static files included.

## Steps to reproduce

```bash
curl -s -D - -o /dev/null -H "Accept-Encoding: gzip, br" \
  https://quickpizza.grafana.com/_app/immutable/assets/0.kLK4yNcK.css \
  | grep -iE "content-length|content-encoding|cache-control|etag|set-cookie"
```

## Expected result

```
content-encoding: br            (or gzip)
cache-control: public, max-age=31536000, immutable
(no set-cookie)
```

## Actual result

```
content-length: 16151
set-cookie: AWSALB=…; Expires=…; Path=/
(no content-encoding, no cache-control, no etag)
```

## Impact

- The 16 KB stylesheet takes an extra ~135 ms to download on a 140 ms-latency connection. Gzip would make it ~4 KB.
- Returning visitors download all ~18 files again, or depend on browser guesswork, instead of using their cache.
- The effect is largest on mobile networks.
