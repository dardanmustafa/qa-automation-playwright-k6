# BUG-011 · QuickPizza: `http://` does not redirect to HTTPS, it times out

| Field | Value |
|---|---|
| Type | Configuration (hosting) |
| Severity | Medium |
| Priority | Medium |
| Area | QuickPizza › hosting / load balancer |
| Environment | <https://quickpizza.grafana.com> (AWS us-east-2 load balancer) |
| Reproducible | Always |
| Found by | HTTP/S response analysis during the load test ([`load/response-analysis.js`](../load/response-analysis.js), request 6) |

## Summary

Opening the site with `http://` (typed without "https", or from an old link) does not redirect to the secure site. The connection simply hangs until it times out. HTTPS responses also don't send a `Strict-Transport-Security` (HSTS) header, which would tell browsers to always use HTTPS.

## Steps to reproduce

```bash
curl -s -o /dev/null -m 10 -w "%{http_code} %{errormsg}\n" http://quickpizza.grafana.com/
# 000 Connection timed out after 10002 milliseconds

curl -s -D - -o /dev/null https://quickpizza.grafana.com/ | grep -i strict-transport
# (nothing)
```

## Expected result

- `http://quickpizza.grafana.com/` answers immediately with `301` or `308` and `Location: https://quickpizza.grafana.com/`.
- HTTPS answers include e.g. `Strict-Transport-Security: max-age=31536000`.

## Actual result

- Port 80 never answers; clients wait until their own timeout (10 s in the test).
- No HSTS header.

## Impact

Visitors who type the address in a browser or tool that doesn't upgrade to HTTPS automatically see a long wait and then an error.
