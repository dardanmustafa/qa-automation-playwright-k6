# BUG-007 · A new demo shop sometimes answers 502 Bad Gateway or hangs during its first minute

| Field | Value |
|---|---|
| Severity | Medium |
| Priority | Medium |
| Area | Demo environment (demo.prestashop.com instance start-up) |
| Environment | demo.prestashop.com front-office demo, PrestaShop 9 instances, Cloudflare in front |
| Reproducible | Intermittent: seen on 3 of about 10 new shops on 23 Oct 2026 |
| Found by | Exploration before writing the tests; the UI suite now protects itself with a health check (see Notes) |

## Summary

`demo.prestashop.com` creates a temporary shop for every visitor and shows it as soon as it has an address. Sometimes that shop is not ready yet:

- for up to about a minute some pages answer **502 Bad Gateway** (from Cloudflare)
- some pages don't answer at all within 30–60 seconds
- the search finds nothing because its index is not built yet

## Steps to reproduce

1. Open <https://demo.prestashop.com/#/en/front>.
2. As soon as the shop appears, open some of its pages directly in the same browser: `/registration`, `/search?controller=search&s=mug`, `/cart?action=show`. The shop's address is the `src` of the `#framelive` iframe, e.g. `https://boss-riddle.demo.prestashop.com`.
3. Repeat with a few new shops (a new visit gives a new shop).

## Expected result

Every page answers normally (200) from the moment the shop is shown, and search finds the existing products.

## Actual result (logs from three affected shops)

Shop 1 (`dashing-drain`):

```
/                         200   8341 ms
/search?…&s=mug           200   "Nothing to search for" (mug products exist)
/3-clothes                502   Bad gateway
/login                    no answer within 30 s
```

Shop 2 (`domineering-lip`):

```
/                         200   6461 ms
/3-clothes                200   1828 ms
/login                    200    617 ms
/registration             502    289 ms   "prestashop.com | 502: Bad gateway"
/6-accessories            no answer within 60 s
/search?…&s=mug           502    212 ms
/cart?action=show         502    208 ms
```

Shop 3 (`sure-cheese`): `/registration` gave no answer within 45 s, right after the first four pages loaded fine.

Waiting about 45–60 seconds after the shop appears was always enough: afterwards every page answered in 0.3–1.8 s.

## Impact

- Demo visitors (potential PrestaShop customers) can hit errors in their first minute.
- Anyone who automates tests against the demo gets random failures.

## Notes

- **Workaround used in this project:** [`ui/global-setup.ts`](../ui/global-setup.ts) checks five key pages (including that search really returns products). Tests start only after two clean rounds in a row. Since then, the full suite has run without retries.
- Suggested fix: only show the shop (or report it as ready) after a health check like that one has passed on the server side.
