# IMP-002 · OSM API: answer 405 Method Not Allowed for unsupported HTTP methods

| Field | Value |
|---|---|
| Type | Improvement suggestion (not a defect: matches the documented behaviour) |
| Priority | Low |
| Area | OpenStreetMap API 0.6 › routing |
| Environment | `https://master.apis.dev.openstreetmap.org/api/0.6` (official development server) |
| Found by | API exploration. `API-NOTE-10` in [`api/tests/notes.spec.ts`](../api/tests/notes.spec.ts) checks the current behaviour |
| History | First filed as BUG-009, then reclassified after checking the OSM documentation (see below) |

## Summary

Using an HTTP method an endpoint does not support (e.g. `PUT` on a note) returns **404 Not Found**, the same answer as for a note that does not exist.

## Why this is not a bug

The [OSM API documentation](https://wiki.openstreetmap.org/wiki/API_v0.6) lists 404 for this case: for creating, commenting, closing and reopening notes it says a 404 "also applies, if the request is not a HTTP POST request". The OSM maintainers explain that the Rails routing treats the method as part of the route, so any request without a matching route gets 404 ([rails-dev, May 2022](https://lists.openstreetmap.org/pipermail/rails-dev/2022-May/023710.html)). HTTP does not require 405 here; it is the more precise answer.

## Current behaviour

```bash
# an existing note
curl -i "https://master.apis.dev.openstreetmap.org/api/0.6/notes/351990.json"         # 200
curl -i -X PUT "https://master.apis.dev.openstreetmap.org/api/0.6/notes/351990.json"  # 404
curl -i -X POST "https://master.apis.dev.openstreetmap.org/api/0.6/capabilities.json" # 404
```

The 404 comes with the HTML page "Couldn't find a file/directory/API operation by that name". The note itself is not affected.

## Suggestion

Answer `405 Method Not Allowed` with an `Allow` header listing the supported methods (e.g. `Allow: GET, DELETE` on `/notes/{id}`).

## Benefit

Developers would see that they used the wrong method, instead of being told that the note does not exist.
